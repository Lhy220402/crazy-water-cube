## 4. 机制契约（改动前必读）

### 4.1 固定合成链与计分

| 材料 | 产物 | 基础分 |
| --- | --- | --- |
| 军 ×2 | 赢² | +4 |
| 赢² ×2 | 水³ | +8 |
| 水³ ×2 | Lec | +16 |
| Lec ×2 | OLD FIVE | +32（假通关） |
| OLD FIVE ×2 | 随机词条（图鉴 +1） | +64 |
| 任意词条 ×2 | 再随机一条词条 | +64 |

- 4×4；单步内每枚方块最多参与一次合成（不连锁）。
- 实际得分 = 基础分 × 当前增益倍率（四舍五入取整）。
- 词条之间**不看名字、不看稀有度**，同为词条级（rank=codexRank=5）即合。

### 4.2 特殊配方（相撞即合，无序匹配，优先于同级判定）

| 材料 | 产物 | 基础分 | 增益 |
| --- | --- | --- | --- |
| 隋 + 军 | 隋军 | +64 | ×2，持续 8 步 |
| 隋·环 + 军 | 隋军·环 | +128 | ×3，持续 12 步 |
| Li + Na | 李娜 | +128 | ×2，持续 8 步（与隋军同梯队） |
| 记 + 赢² | 记赢赢 | +256 | **真通关** + 本局永久 ×2 |

- 增益创建当步**不生效也不消耗**，从下一步开始倒数；多个增益乘算叠加。
- 特殊产物也是词条级方块：可与任意词条继续合成（被消耗时增益不撤销）。
- 特殊产物触发即收录图鉴；首次触发弹解释卡。
- 配方与产物定义集中在 recipes.ts；加配方只改那里 + lore.ts。
- `TileMatcher` 支持 `{rank}` 与 `{variant}` 两种写法；Li+Na 是 `variant × variant` 配方，
  `matches()` 对 variant 只比较词条 id，不看等级。

> **隐藏契约（重要）**：真通关配方（记 + 赢² → 记赢赢）是隐藏内容，游戏内不得提示——
> 记方块的词条池定义里**不写** `recipe`（不显示 +赢² 角标）；合成链页在该产物首次触发前
> **整行隐藏**；假通关弹层与「关于」简介都不写配方；棋盘提示只写「词条之间藏着特殊组合」。
> 隋/圈隋 的 +军 提示可以保留（非真通关内容），Li+Na 配方行也公开（产物首次触发前打码）。
> 改 UI/文案时别把配方加回去（测试里有专门断言）。

### 4.3 生成规则

- 每次有效移动后随机空格生成一枚：90% 军 / 10% 赢²（DEFAULT_SPAWN）。
- 开局 2 枚，分数 0，无增益，won/trueWon 均 false。

### 4.4 假通关 / 真通关

- 首次合出 OLD FIVE → justWon=true，won=true 持久化，弹「真通关了吗？」（礼花），不重复弹。
- 首次合出 记赢赢 → justTrueWon=true，trueWon=true 持久化，弹「真·通关！」（更大礼花），不重复弹。
  **游戏内不提示这个配方如何触发**（见 4.2 隐藏契约），弹层只在触发后解释。
- 弹层优先级：真通关 > 假通关 > 首次收录解释 > 结束。
- 撤销按快照恢复 won/trueWon/buffs（与原版语义一致）；图鉴收录永不回退。

### 4.5 图鉴收集与悬念

- 词条池（CODEX_ENTRIES，权重，总和 37）：
  隋(common,6) / 鳄鱼鳍(rare,3) / 隋·环(rare,2,ring) / 鳄食菌(legend,1.2) / 记(legend,0.8) /
  八一(rare,2) / 红梅(rare,2) / 金山(rare,2) / 浮力(rare,2) / Li(rare,2) / Na(rare,2) /
  小明(rare,2) / 燕子(rare,2) / 豆包AI(rare,2) / 彪(rare,2) / 会成(rare,2) / 🌧️(rare,2)。
- 特殊产物（PRODUCTS，不进抽取池，触发即收录）：隋军 / 隋军·环 / 李娜 / 记赢赢，共 4 条。
- 稀有度只影响显示与抽取概率，不影响配对。允许重复，重复累加次数。
- 未收录前词条页空白：一句「图鉴还是空白的」+ 一张问号卡；不剧透名字、不显示 x/y；
  集齐后显示「全部收录 · 共 21 条」（N = 池 17 + 特殊 4）。
- 合成链页：4 固定行 + 1 词条入口行 + 可见特殊配方行（隋系 2 行 + 李娜 1 行；真通关配方行
  首次触发前隐藏）。配方配对公开（玩法需要），产物名字与增益在首次触发前打码（？？？ + 问号 mini）。
  初始 8 行；真通关触发后 9 行。
- 首次抽到词条 / 首次触发特殊合成 → 弹解释卡（lore.ts 文案已全部补齐）。
- 收录跨局累积；重新开局不清空；撤销不回退；读档过滤池外 id。

### 4.6 存档与撤销

- localStorage key（前缀 jun2048 不变）：
  - `jun2048`：棋局（SavedGame **v3**）
  - `jun2048.best`：最高分
  - `jun2048.codex`：图鉴 `{ [entryId]: count }`（含特殊产物 id）
  - `jun2048.theme`：外观偏好 auto/light/dark
- 开场界面**不写入任何新 key**，每次打开页面都出现一次；「继续游戏」由是否有棋局存档决定。
- 等级签名 `jun|win|water|lec|liu`（liu 是 OLD FIVE 的存档身份，改名不改 id）。
- v3 兼容读 v1/v2；**词条 variant 必须存在于当前池或特殊产物表，否则整档判坏**（换池子后旧档开新局）。
- 每步移动后立即存档；pagehide 再存；存档失败不影响游戏。
- 撤销最多 20 步整局快照；撤销后最高分不回退、图鉴不回退。
- 无路可走 → over=true 弹结束层；读档死局启动时也弹，但 **开场界面开着时先不弹**，
  等玩家点「继续游戏」后再弹（app.ts 的 pendingGameOver）。

### 4.7 输入与交互

- 触摸 Pointer Events，阈值 max(14, min(28, 棋盘宽×0.05))px，主轴判定。
- 键盘方向键/WASD 移动，Z 撤销，Esc 关弹窗；开场界面 Enter / Space 进入。
- 开场界面开着时棋盘输入全部忽略（app.ts 的 `intro?.isOpen()` 守卫）。
- 动画期间输入串行化：忙时只留一个方向队列 queued，弹窗/撤销用 pending 延后。
- 弹窗打开禁止棋盘移动；遮罩点击关闭；焦点打开/关闭时恢复。

### 4.8 音频（v2.2 已实现：合成后播放猫叫）

- 音源：用户微信语音「语音 010_W_20261102_092315.m4a」的**第二声猫叫**（1.15s–2.05s），
  经 ffmpeg 降噪（`afftdn`）、高通、`loudnorm` 归一化，转 64kbps 单声道 mp3，
  base64 内联在 `src/ui/merge-sfx.ts`（由 `scripts/audio.mjs` 生成，勿手改）。
- `src/ui/audio.ts` 的 `createAudio({w})` 返回 `AudioEngine`：`unlock / play / setEnabled /
  setVolume / startMusic / stopMusic / destroy`，app.ts 调用点不变。
- 只有合成类 cue 出声：merge（原声）、special（×1.12）、win（×1.22）、truewin（×1.32）；
  move / invalid / undo / restart / collect / start / over 保持静默。一次移动里有多次合并也只播一次。
- 解锁：app.ts 在「开始合成 / 继续游戏」时调用 `unlock()`；无 AudioContext（旧浏览器 / jsdom）
  时全部安全降级。解码用回调式 `decodeAudioData`，兼容 Safari 14.1。
- 不写 localStorage、不加第 5 个 key；静音 / 音量只在本次会话生效。`startMusic()` 目前只记状态，
  不播背景音乐。
- 单文件契约：音频只能是 data URI / WebAudio 合成，不能外链；`verify-dist` 会检查内联音效存在。

## 8. 踩过的坑（别踩回去）

1. **String.replace 的 $& 陷阱**：内联压缩 JS 必须用函数替换 `html.replace(marker, () => content)`。
2. **esbuild target**：用 safari14.1（safari14 报 destructuring 不支持）。
3. **jsdom 跨 realm**：state.cells / state.buffs 是页面领域数组，deepStrictEqual 会误判；
   用 Array.from(...) 或长度/逐项断言。
4. **jsdom 没有布局**：clientWidth 为 0，layout() 宽度 ≤0 直接返回；ResizeObserver 需 'ResizeObserver' in w 保护。
5. **localStorage 可能抛异常**：storage.ts 的 KV 必须 try/catch 退回内存。
6. **弹层过渡**：先 hidden=false → 强制 reflow（void offsetWidth）→ 加 is-open。
7. **弹层文案不要写 Markdown 星号**：textContent 会原样显示。
8. **词条方块必须有合法 variant**：v3 读档时 variant 不在池/特殊表 → 整档判坏（换池子的设计如此）。
9. **加词条不影响棋局存档**：签名只含等级 id；图鉴按 id 独立存、读档过滤。
   但**加词条会让图鉴总数、抽取权重、以及测试里的固定期望值变化**，改池子后要同步 tests 与文档。
10. **npm test 依赖 dist**：先 build 再 test，别拆。
11. **CSS 压缩会去掉属性选择器引号**：[data-theme="dark"] → [data-theme=dark]，
    静态自检的正则要兼容两种写法。
12. **增益展开别带定义字段**：BuffDef 有 moves，Buff 只有 movesLeft；
    构造 Buff 时逐字段赋值，不要 {...def, movesLeft}（会把 moves 带进存档）。
13. **深色 token 有两份**：@media 块与 [data-theme=dark] 块内容必须同步改（v2.1 的 --intro-veil 也是）。
14. **真通关是隐藏内容**：别在记方块的 `recipe`、合成链、假通关文案、关于简介里写
    「记 + 赢²」；测试里专门断言了这些位置不含泄露文案。
15. **开场界面会挡住输入**：所有棋盘输入都要过 `intro?.isOpen()` 守卫；
    jsdom 测试 boot() 默认自动跳过，新测试别忘。读档死局要等进入游戏再弹结束层。
16. **variant×variant 配方**：Li+Na 是两个 `{variant}` matcher；`matches()` 只比较 id，
    不要求 rank，但两枚实际都是 codexRank。加同类配方照这个写法即可。
17. **词条色相有两层来源**：显式 hue/hue2 优先；特殊产物不在抽取池里，所以 board/sheet 用
    `huesOf(entry, entries, id)`（传 entry 对象），不要只传 `config.codex.entries` 查特殊产物。
18. **音频接口是空实现**：不要在 `createAudio` 构造时创建 AudioContext（会被自动播放策略拦），
    等 `unlock()`；也不要在 play 里写存档。单文件不能引外部音频，只能 data URI / WebAudio 合成。
19. **GitHub 仓库名只支持 ASCII**：试图把仓库名改成「疯狂水立方」会被归一成 `-`，
    API 返回 200 但名字已坏（真实 slug 是 `crazy-water-cube`，中文名只能写在简介/描述里）。
    Gitee 可以改显示名（name），但路径（path）仍是 `jun2048`。
20. **音频必须内联**：`merge-sfx.ts` 里的 base64（约 10 KB）由 `scripts/audio.mjs` 生成，
    构建时随 JS 一起进单文件；不要改成外链 mp3/m4a。`verify-dist` 检查 data URI 与
    `decodeAudioData`。重新裁剪音频后要重跑 `npm run verify`，并确认单文件体积仍在可接受范围。
21. **无 AudioContext 必须静默**：jsdom 和旧浏览器没有 AudioContext；`createAudio` 不能因此抛错。
    解码用回调式 `decodeAudioData`（Safari 14.1 的 promise 式不保证），且只在 `unlock()` 后创建。
22. **加词条会动测试固定值**：随机池 14→17 时，权重总和 31→37、固定 rng 抽中项从「红梅」变「金山」、
    图鉴总数 18→21、坏档测试里拿 `biao` 当「未知 id」会失效（这次就踩了）。
    加词条后要全局搜测试里的数量、id 列表和固定期望。
23. **emoji 词条按码点算长度**：`🌧️` 是 2 个码点，`[...text].length` 得 2 → `is-s1`；
    不要用 `text.length`（会是 3）判字号。多行解释靠 CSS `white-space: pre-line`，不是 `<br>`。
